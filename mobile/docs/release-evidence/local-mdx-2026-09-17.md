# Local MDX dictionary release evidence — 2026-09-17

## Product path

- The formal offline text reader exposes a local dictionary action. Selected
  text is queried first; users can also type a term manually.
- Native imports copy MDX and optional same-name MDD files into the application
  documents directory. Metadata stores generated IDs, sizes, SHA-256 hashes,
  entry counts, enablement, ordering, and import time. Original picker paths are
  not retained.
- Multiple dictionaries can be enabled, disabled, reordered, and removed.
  Removal deletes only the application-owned copy.
- Queries stay on-device. Loaded files are checked against their recorded size
  and SHA-256 before use.

## Format and rendering coverage

- MDX/MDD engine version 2 containers.
- Stored, zlib, and LZO1X blocks with Adler-32 checksums and bounded expansion.
- UTF-8 and UTF-16 keys, including MDD libraries that omit `Encoding` and use
  implicit UTF-16 keys.
- Duplicate definitions, bounded `@@@LINK=` redirects, cycle rejection, MDD
  image resources, `sound://` pronunciation resources, and entry links.
- Definition HTML is parsed into an allowlist. Scripts, forms, frames, embedded
  objects, event attributes, remote URLs, unsafe paths, unsafe CSS, and active
  content are removed. Local inline and MDD-hosted CSS is reduced to a bounded
  presentation-only property and selector subset.

Encrypted dictionaries, MDX 1.x, unsupported text encodings, malformed block
tables, unsafe resource paths, checksum failures, and configured size-limit
violations fail closed.

## Independent compatibility checks

The repository does not redistribute external dictionary files. The verifier
at `tool/verify_mdx_dictionary.dart` was run against independently produced and
public samples:

- `zhansliu/writemdict` commit `f0240b30cabd2f0470d3ee1a0641fc7f8c38dcf5`
  v2 output: zlib MDX, stored MDX, and an MDX/MDD pair all parsed successfully.
- `KnIfER/mdict-java` public `MdbR.mdd`, SHA-256
  `0dbb30d486cfaaae5bb3671ed3a9d934db987cd4a67bb930affdc40d28218bb5`
  (verify the current upstream hash before reproducing): 17 resources parsed.
- `terasum/js-mdict` public truncated Oxford index samples were used only to
  check real v2 header/index conventions and large-count bounds. The parser
  correctly rejects the intentionally incomplete record payload instead of
  treating it as a complete dictionary.

## Automated verification

- VM parser tests cover stored/zlib/LZO, a real liblzo1x vector, MDD binary
  resources, little-endian header checksums, redirects, corruption, encryption,
  and size bounds.
- Service tests cover restart persistence, ordering, enablement, removal,
  MDD lookup, and tamper detection.
- Rendering tests cover active-content removal, remote-resource blocking,
  image MIME allowlisting, entry links, `sound://`, and local CSS sandboxing.
- A widget test verifies selected text lookup from the formal offline reader.
- Chrome tests exercise zlib MDX and real LZO1X decompression.

The final local and remote run identifiers are recorded in the delivery report
for the commit containing this evidence.
