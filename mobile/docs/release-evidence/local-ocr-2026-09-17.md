# Local OCR release evidence — 2026-09-17

Scope: production wiring for device-only image text recognition.

## Implemented matrix

| Platform | Engine | Chinese | English | Input entry |
| --- | --- | --- | --- | --- |
| Android | Bundled Google ML Kit | Simplified | Yes | Gallery/file + camera |
| iPhone / iPad | Apple Vision | Simplified | Yes | Gallery/file + camera |
| macOS | Apple Vision | Simplified | Yes | File |
| Windows | Windows.Media.Ocr | With installed `zh-Hans` pack | With installed `en-US` pack | File |
| Linux | Bounded built-in bitmap recognizer | No | High-contrast PNG only | File |
| Web | None | No | No | Hidden |

There is no HTTP client, socket, persistence API, or remote fallback in the OCR
adapter. Shared validation rejects empty, malformed, non-PNG/JPEG, oversized,
or excessive-dimension input before native dispatch.

## Automated evidence

- Flutter static analysis: zero issues.
- OCR/service/widget regression tests cover real portable PNG recognition,
  Chinese native-channel results, JPEG admission, memory limits, cancellation,
  platform gating, camera entry, and no network/persistence imports.
- Android debug APK builds with both bundled ML Kit models.
- Final whole-suite and five-platform CI run links are recorded in the delivery
  report after the pushed revision completes.

## Remaining external acceptance

Physical-device photo quality, permission denial/recovery, background/foreground
transitions, low-memory behavior, and the Windows optional Chinese language pack
still require the corresponding real hardware/OS environments. These are
release acceptance checks, not silently claimed by unit or hosted build tests.
